## DDL rules applied (all from the model)
- Every object schema-qualified `bpa.`; `CREATE SEQUENCE bpa.workpack_number_seq MAXVALUE 999999 NO CYCLE` (A2). The schema itself
  already exists from `backend/postgres/init/01-create-databases.sql`; V1 does not create it (see Q1).
- PK `id uuid DEFAULT gen_random_uuid()`; exception `app_user.username text PRIMARY KEY`.
- Audit columns on every table except `audit_log`, placed last, in this order: `created_at timestamptz NOT NULL DEFAULT now()`,
  `created_by text NOT NULL`, `updated_at timestamptz NOT NULL DEFAULT now()`, `updated_by text NOT NULL`.
- Every FK written with explicit `ON DELETE NO ACTION`. Deferred (`DEFERRABLE INITIALLY DEFERRED`) only where the model says so:
  the `workpack_material` composite FK to `workpack_phase(workpack_id, phase)` and `UNIQUE (workpack_id, phase, material_ref)`.
- Enums as `text` + `CHECK (col IN (...))` per §7.1; `wp_outcome` CHECK per §5.2; `user_role_scope.group_id` CHECK on the seven §1.6 groups.
  `assignment_file_row.outcome` has no value CHECK (§7.3), only `CHECK (outcome IS NOT NULL OR wp_outcome IS NOT NULL)`.
- Defaults only where the model states them: `workpack.status 'Draft'`, `hour_journal_header.locked false`,
  `hour_journal_line.status 'Open'`, `digital_timesheet.submission_status 'Draft'`, `published_message.published_at now()`.
- Indexes only as stated: `assignment_file(sha256)` (not unique), `audit_log(table_name, record_id)`, partial unique index on
  `assignment_file_row(assignment_file_id, workpack_number, badge_no) WHERE row_number IS NULL`. No FK-column indexes.
- `UNIQUE NULLS NOT DISTINCT` on `user_role_scope` (PostgreSQL 15+; compose pins 17).
- Worker-checked rules (§1.5) are not put in the database.
- Comments carry the canonical label only (§1.3, A9). Table comment on all 31 tables; column comments by the §7.2 rule
  (column label differs from the table label), 19 tables.
- File layout: one section per table in dependency order: A (12), B (6), C (5), D (4), F (2), E (1), G (1). F precedes E because
  `notification` references `app_user`. Each section: `CREATE TABLE`, extra indexes, `COMMENT ON`.

## Seed plan (R__seed_reference_data.sql)
- Parents before children. Each table: a header comment block naming its SOR (and the real SOR where the table label differs),
  then `INSERT ... ON CONFLICT (<business key>) DO UPDATE` setting the non-key columns and `updated_at`/`updated_by`.
  Audit columns `created_by = updated_by = 'seed'`. No `DELETE`. No `TRUNCATE`.
- `drawing_revision` upserts only the seed's own `(drawing_ref, revision)` pairs; rows written at runtime are never touched (A8).
- Business keys: `project_ref`, `wbs_ref`, `activity_ref`, `cbs_activity.activity_ref`, `department_ref`, `material_ref`,
  `drawing_ref`, `(drawing_ref, revision)`, `design_dwg_ref`, `employee_ref`. `cutting_sheet` and `material_reservation` have no
  UNIQUE in the model: seeded with `UPDATE` then `INSERT ... WHERE NOT EXISTS` (Q4).
- Not seeded: `app_user`, `user_role_scope`, all Work Pack, assignment, hours, notification and audit tables, scenario data.

## Questions
All eight answered by Ahsan on 29 Oct 2026 (approval of this plan).
- **Q1 (Flyway history): accepted.** `flyway_schema_history` stays in `bpa`; the comment check excludes it by name. V1 does not run `CREATE SCHEMA`
  (the init script creates `bpa`; the throwaway database gets the same schema before Flyway runs).
- **Q2 (table label for `project_job_code`, `cbs_activity`): decided.** Rule: label the table with the SOR of its business key (its UNIQUE column,
  §1.1 N4) and comment the other column. `project_job_code` = D365 F&O Project Management, `job_code_ref` commented FMS. `cbs_activity` = P6 via
  D365 PMS (`activity_ref`), `cbs_code_ref` commented D365 F&O Cost Control Report. **ASSUMPTION: for Khitaba to check.** Not blocking: comments are
  cheap to change before V1 is frozen (ADR 0010).
- **Q3 (`material_reservation`): decided.** Table = D365 F&O PPC. All three columns are commented, as §3.9 says; the comment on `traceability_number`
  repeats the table label, which satisfies §3.9 and §7.2 (the CI rule requires comments only where the SOR differs).
- **Q4 (seed without UNIQUE): accepted**, no schema change. `material_reservation` matched on `(traceability_number, drawing_ref, material_ref)`
  (reservations keyed by drawing + material, C5); `cutting_sheet` matched on `(cutting_sheet_ref, drawing_ref)`. Both: `UPDATE` then
  `INSERT ... WHERE NOT EXISTS`.
- **Q5 (look-ahead): accepted.** 6 of 8 drawings have a row, dates spread over three weeks (§3.11). DWG-118 has a row (BPA-11); at least one drawing has none (§11).
- **Q6 (workers): accepted.** 12 ordinary workers; "inactive" seeded as ordinary, "another department" not seedable (§11, Q-DM5, recorded ASSUMPTION). Named rows:
  E1021, E1099, E1150 (no cost centre), E2001 (agency). E9999 does not exist.
- **Q7 (names): accepted.** PostgreSQL default names; only `assignment_file_row_synthetic_uk`, `assignment_file_sha256_idx` and
  `audit_log_table_record_idx` are named.
- **Q8 (defaults): accepted, "none unless stated".** Applied: `id gen_random_uuid()`, `created_at`/`updated_at now()`, `workpack.status 'Draft'`,
  `hour_journal_header.locked false`, `hour_journal_line.status 'Open'`, `digital_timesheet.submission_status 'Draft'`,
  `published_message.published_at now()`. `created_by` and `updated_by` have no default.
